# Forma UI v0.1 Implementation Plan

> **For agentic workers:** each task below is dispatched as its own brief, in its own worktree and branch, and is reviewed independently on a pinned commit before it lands through a pull request. The brief expands the task into test-first steps (failing test, minimal implementation, passing test, commit). Steps use checkbox (`- [ ]`) syntax for tracking. Do not start a task whose dependencies have not landed on `main`.

**Goal:** Ship Forma UI v0.1. That is a token source with deterministic outputs, six accessible React components extracted from Resolve, and a bilingual documentation site on GitHub Pages. Resolve then consumes the built package with no behavior change.

**Architecture:** One repository with npm workspaces:
- `packages/forma-ui` is the library: tokens, base CSS and React components, built in Vite library mode.
- `site/` is the documentation site: a static Vite + React single-page app with per-route HTML entry points, consuming the **built** library.

The token source is DTCG JSON. A small in-repo generator emits CSS, TypeScript and a Figma variables file from it. Design specifications for the site come from a committed export of the Figma file, produced by the project's own Figma plugin.

**Tech Stack:** Node ≥ 22.12, npm workspaces, TypeScript 6, React 19 (peer), Vite 8, Vitest 5 (jsdom plus browser mode with Playwright), Playwright 1.63, oxlint, Prettier, CSS Modules, React Router 7 (site only), FormatJS `react-intl` (site only), GitHub Actions, GitHub Pages.

**Spec:** `CLAUDE.md`, `AGENTS.md` and `docs/design-handoff.md`, plus the Figma file https://www.figma.com/design/jOLY73sXOjkAXs5OxNeeBW (page 07, `node-id=5-6304`; library pages 00–04).

## Global Constraints

- Resolve reference commit: **`c3f02f8`** (github.com/Yelison/resolve). Every inventory, snapshot and parity test cites it.
- The library has peer dependencies `react` and `react-dom` `^19.2`. It bundles no React and no copy of `react/jsx-runtime`.
- The library does not depend on React Router, TanStack Query, any i18n library, application services or product storage.
- The library ships no hard-coded user-facing copy in one language:
  - built-in strings have **English** defaults;
  - each one can be overridden through a prop and through `FormaProvider`;
  - Resolve keeps its Spanish strings.
- Site URLs are English and identical in both languages, with no locale segment. Language resolution order: stored choice, then the browser (`es*` → `es`, `en*` → `en`), then `en`.
- Every visible site string, `aria-label`, `<title>` and meta description exists in `en` and `es`.
- Code, component names, props and token names stay English in both languages.
- The site supports light, dark and system themes, with no theme or language flash on first paint.
- Layout checks run at 320, 390, 767, 768, 1024, 1199, 1200 and 1440 px, in both themes, with no horizontal scroll and no clipped text.
- Contrast: AA 4.5:1 for text pairs and 3:1 for non-text pairs, for every pair actually painted.
- Public CSS variable names from Resolve (`--color-*`, `--font-*`, `--space-*`, `--radius-*`, `--control-height`, `--button-height`, `--touch-target`, `--focus-ring`, `--duration-*`) are not renamed in v0.1.
- Nothing is published to npm and no GitHub Release is created without the owner's authorization. The site is deployed only from `main` through the Pages workflow.
- Every change lands through a PR with rebase merge, and each commit passes the checks of its layer on its own.
- Test runners on shared machines use capped workers: Vitest `--maxWorkers=3`, Playwright `--workers=3`.

## Review Focus

1. **A Spanish user's first visit to a deep link** (for example `/docs/components/button` opened from a shared URL, with an `es-ES` browser and nothing stored).
   - Expected: the page renders in Spanish with `<html lang="es">`, the right `<title>` and no flash of English.
   - Test owner: Task 4.2, an e2e test with `locale: 'es-ES'` that reads `document.documentElement.lang` and the `<h1>` before hydration settles.
2. **A Resolve screen that relied on Spanish defaults after adoption**, for example a submitting `Button` with no `loadingLabel`.
   - Expected: it still announces «Enviando…», because Resolve installs Spanish strings through `FormaProvider`.
   - Test owner: Task 5.2, a Resolve unit test that renders `Button loading` inside Resolve's provider and asserts the accessible name.
3. **The user's theme choice and the system preference disagreeing on reload** (stored `light`, OS dark).
   - Expected: light is painted from the first frame, and switching to `system` follows the OS live.
   - Test owner: Task 1.3, a browser-mode test with emulated `prefers-color-scheme: dark` and a stored preference.
4. **Keyboard-only use of a Dialog containing a Tooltip trigger.**
   - Expected: Escape closes only the tooltip first, then the dialog. Focus returns to the opener, and Tab never leaves the dialog.
   - Test owner: Task 3.3, a browser-mode test (real `showModal`, not the jsdom polyfill).
5. **Long Spanish copy and the pseudo-locale in the collapsed navigation and mobile drawer at 320 px.**
   - Expected: no clipped labels, 44 px targets and no horizontal scroll.
   - Test owner: Task 4.2, an e2e test over the pseudo-locale at 320 and 768 px that asserts `scrollWidth <= clientWidth` and target sizes.

### 1.2 Resolve at `c3f02f8` (the source of the shared components)

**Tooling**
- npm (lockfile v3) and Node ≥ 22.12.
- React 19.3, TypeScript 6.0 (strict, `verbatimModuleSyntax`, `erasableSyntaxOnly`) and Vite 8.3.
- Vitest 5 with jsdom; `src/test/setup.ts` polyfills `showModal`.
- Playwright 1.63, Chromium only.
- oxlint and Prettier (no semicolons, single quotes, width 120).
- CSS Modules plus `lib/cx`, no path aliases, a single barrel `components/ui/index.ts`.
- No Storybook, no axe and no i18n library. Everything is Spanish and `<html lang="es">`.

**Tokens**
- `frontend/src/styles/tokens.css` holds 25 color tokens per theme and the typography and spacing scales.
- Light is in `:root`. Dark is declared twice, byte-identical, in `@media (prefers-color-scheme: dark) :root:not([data-theme='light'])` and in `:root[data-theme='dark']`.
- `global.css` adds radius, sizing, shadow, motion and app-layout tokens, the reset, the focus ring, `.visually-hidden`, `html.scroll-locked` and the reduced-motion override.
- There is no z-index scale. Literal values run from 20 to 200, and Tooltip uses 90.
- `--shadow-popover` is a literal rgb that does not follow the theme.
- `tokens.contrast.test.ts` checks 40 pairs per theme (AA text and 3:1 non-text) and asserts that the two dark blocks are equal.
- `tokens.keycloak.test.ts` requires the identity provider's login theme to carry a **byte-identical** copy of `tokens.css`, and bans literal colors in that theme.

**Theme**
- `app/theme/theme.ts` and `useTheme.ts` implement light, dark and system, stored under `resolve-theme` with `useSyncExternalStore`.
- An inline script in `index.html` sets `data-theme` before first paint.
- Components never read the theme; they only use CSS variables.

**Components:** 37 folders in `frontend/src/components/ui`. v0.1 set:

| Component | Areas using it | Built-in copy | Literals breaking ADR criterion 4 | Notes |
| --- | --- | --- | --- | --- |
| Button / IconButton | 8 / 2 | `loadingLabel = 'Enviando…'` | spinner 16px, 0.8s | loading keeps focus (`aria-busy`, `aria-disabled`); IconButton 44×44 |
| Badge | 4 | none | `min-height: 28px` | tones blue/green/amber/red/neutral |
| Field / Input | 0 (internal) / 5 | none | none | Input imports `Field.module.css`; tests live in `Field.test.tsx` |
| Tooltip | 0 (inside NavItem, Sidebar) | none | 240px, z-index 90 | render-prop trigger; Escape in capture phase; portals into an open `<dialog>` |
| Modal (Dialog) | 4 | none | 440/640px, 8px keyframe | native `<dialog>` + `showModal`; backdrop click needs press **and** release on the backdrop; focus return; scroll lock |
| Icon | 4 | none | — | 23 bespoke paths in `Icon/paths.ts`, generated from Figma; closed `IconName` union |

- The helpers that travel with v0.1 are `lib/cx`, `lib/position` (Tooltip), `lib/scrollLock` (Modal) and `shared/useFloating` and `shared/useModalDialog`.
- Domain or shell components that stay in Resolve: TicketRow, Message, Editor, Timeline, Sidebar and Topbar.
- Generic later: Checkbox, Switch, Tabs, NavItem (needs a link slot instead of `NavLink`), Select, Textarea, Alert, EmptyState, Toast, Pagination, Skeleton and Menu.

**ADR 0001** (`docs/decisions/0001-forma-ui-extraction.md`) extracts a component only when a second real consumer exists, and lists five criteria:
1. three or more product areas and no change for a whole phase;
2. documented, stable API;
3. no domain types;
4. token-only visual values;
5. its own tests plus a `/catalogo` entry.

Re-measured at `c3f02f8`:
- every v0.1 component now has JSDoc on all props (13e3e6c);
- the catalog lists every export except Field and ToastProvider (ec0bffe, 711d1a9);
- every v0.1 component still fails criterion 4 on literal sizes, except Field, Input and IconButton;
- Tooltip and Field fail criterion 1 on direct product areas.

The superseding ADR (Task 0.5) records how each failure is resolved: literal sizes become tokens in Forma UI, and internal-only components travel as dependencies of a component that does qualify.

### 1.3 Gaps the plan has to close

1. **One editable token source.** Today the values live in Resolve's CSS, Resolve's Keycloak copy, and stale Figma variables.
2. **Base and app CSS mixed together.** `global.css` mixes library-level tokens and base styles with Resolve's app layout.
3. **Untested accessibility in real browsers.** Focus containment and the inert background of the dialog are untested, since jsdom only polyfills `showModal`. There is no automated accessibility scan.
4. **Spanish defaults.** Every built-in string and all JSDoc is Spanish.
5. **No bilingual site.**

## 2. Decisions

Each decision states the choice, the reason and what was rejected. Decisions marked **(owner)** wait on the questions in §6.

**D1 · Independent repository with npm workspaces.**
- Choice: `packages/forma-ui` (library) and `site/` (documentation) live in this repository.
- Reasons:
  - Resolve stays untouched while v0.1 is built.
  - The site consumes the library's **built output** through the workspace link, which exercises exports and CSS the way Resolve will.
- Rejected:
  - a workspace inside Resolve (couples release cadence and CI, and the ADR rejected partial extraction there);
  - Turborepo or Nx (two workspaces do not need a task runner).

**D2 · One package, with subpath exports.**
- Package name: `@yelison/forma-ui` **(owner, Q1)**.
- Exports:
  - `.`: components, `FormaProvider`, the theme API and types;
  - `./tokens.css`: tokens only, for consumers without React, such as Resolve's identity-provider theme;
  - `./base.css`: focus ring, `.forma-visually-hidden`, reduced motion and the scroll-lock class;
  - `./styles.css`: component styles;
  - `./theme-script`: the first-paint script as a string;
  - `./tokens.json`: resolved token values.
- Reason: a separate tokens package is justified only by separate ownership or build. Here one build serves both, and the CSS subpaths give non-React consumers what they need.
- Rejected: `@scope/tokens` + `@scope/react` (two versions to keep in lockstep, no second owner).

**D3 · Token source in DTCG JSON plus an in-repo generator.**
- Source: `packages/forma-ui/tokens/*.tokens.json`, in the Design Tokens Community Group format with `$value`, `$type`, aliases `{color.blue-ink}` and theme modes as `$extensions.forma.modes.{light,dark}`.
- `scripts/build-tokens.ts` (about 200 lines, tested) emits:
  - `dist/tokens.css`, in Resolve's exact block structure: `:root`, the two identical dark blocks and `var()` aliases;
  - `src/tokens/tokens.ts`, typed names;
  - `dist/tokens.json`;
  - `figma/variables.json` for the plugin import.
- All outputs are deterministic: sorted keys, fixed formatting, a header naming the source, no timestamps.
- Generated files are never edited by hand; a CI step regenerates them and fails on any diff.
- Rejected:
  - Style Dictionary (a capable tool, but reproducing Resolve's duplicated dark block and alias layout exactly needs custom formats anyway, and the generator is small enough to own);
  - Figma as the source (the owner chose code as the source; Figma variables are regenerated from it).

**D4 · Keep Resolve's native, tested accessibility implementations.**
- Choice: native `<dialog>` + `showModal`, Resolve's tooltip and positioning helper.
- Rejected: replacing them with Radix or React Aria. They are verified in production, small, and dependency-free; a primitive library would change behavior Resolve's tests pin.
- Added testing:
  - **Vitest browser mode (Playwright, Chromium)** for focus, `showModal` and pointer behavior;
  - `axe-core` checks in unit tests and in site e2e (`@axe-core/playwright`).

**D5 · No Storybook in v0.1.**
- Reason: the documentation site *is* the explorer, catalog and reference that the owner designed; Storybook would be a second, unstyled catalog to maintain. Component development uses tests and the site's dev server.
- Revisit if a third consumer needs isolated visual regression. Storybook's port range is reserved, so adding it later costs nothing **(owner, Q5)**.

**D6 · Site: Vite + React SPA with per-route static entries.**
- Routing: React Router 7 in declarative mode, as in Resolve. Base path `/forma-ui/`.
- At build, a route manifest emits one `index.html` per route (`docs/components/button/index.html`…), each with English meta. GitHub Pages then answers deep links with **200**, and `404.html` covers unknown paths.
- An inline first-paint script resolves **language** (stored, then browser, then `en`) and **theme** before React renders; React then renders with `createRoot`.
- Rejected: full prerendering (SSG). Without a locale segment, a prerendered English body hydrated for a Spanish visitor causes a hydration mismatch or a flash of English.
- Trade-off: only the English meta is indexable, which the no-segment rule accepts.
- Pages workflow: reuse Resolve's `pages.yml` once its `showcase-pages` work has merged, adapted to `npm run build -w site` and base `/forma-ui/`.

**D7 · Site i18n: FormatJS (`react-intl`) with ICU messages.**
- Setup:
  - English source messages in `site/src/i18n/en.json`;
  - `es.json` translated alongside;
  - `@formatjs/cli` to extract and compile;
  - `--pseudo-locale en-XA` for the pseudo-locale build used in tests.
- Shared formatting: plurals, dates and numbers go through ICU and `Intl`.
- Guardrails:
  - a typed `MessageId` union generated from `en.json`;
  - a CI check that `es.json` has exactly the same keys;
  - a glossary in `site/src/i18n/glossary.md`. Fixed terms: Forma UI, component names, `token`, `variant`, prop names.
- Language switcher: in the top navigation and the mobile drawer. Options are named `English` / `Español`, each with its own `lang`. The choice is stored under `forma-ui-locale`.
- `<html lang>` follows the active language.
- Rejected:
  - i18next (ICU needs a plugin, and pseudo-localization is not built in);
  - Lingui (its compile-time macros add a Babel/SWC step to a plain Vite build).

**D8 · Library copy: a strings provider with English defaults.**
- `FormaProvider` takes `strings?: Partial<FormaStrings>`.
- Each component also takes the relevant prop (for example `loadingLabel`); the prop wins, then the provider, then the English default.
- `FormaStrings` v0.1:

  | Key | Default |
  | --- | --- |
  | `buttonLoading` | `'Loading…'` |
  | `dialogClose` | `'Close'` (only used if a close button is opted into) |

- The library takes no i18n dependency. Resolve passes `{ buttonLoading: 'Enviando…' }`.

**D9 · Theme runtime in the library.**
- API:
  - `createThemeStore({ storageKey, attribute = 'data-theme' })`;
  - `useTheme()` returning `{ preference, resolved, setPreference, toggle }`;
  - `themeScript({ storageKey })` returning the first-paint snippet.
- This is Resolve's implementation, parameterized. Resolve keeps `storageKey: 'resolve-theme'`; the site uses `forma-ui-theme`.

**D10 · CSS strategy.**
- Components keep CSS Modules. Vite library mode emits one `styles.css` with class names prefixed `forma-`.
- Literal sizes become tokens: `--badge-min-height`, `--spinner-size`, `--tooltip-max-width`, `--dialog-width`, `--dialog-width-wide` and a z-index scale (`--z-sticky` 20, `--z-dropdown` 30, `--z-menu` 80, `--z-tooltip` 90, `--z-toast` 100, `--z-overlay` 200). Values are unchanged, so nothing shifts visually.
- `--shadow-popover` stays the same literal in v0.1 (no visual drift), with an issue to make it theme-aware.
- Resolve's reset and app-layout tokens stay in Resolve.

**D11 · Icons.**
- The package ships Resolve's 23 icons. `Icon` accepts the `IconName` union; site-only icons stay in the site.
- `paths.ts` is generated from the Figma export (Task 0.1 output) by `scripts/build-icons.ts`. Its header names the source, and Prettier ignores it.
- License: MIT (the icons are Resolve's own work).

**D12 · Fonts.** The package does not bundle Inter. `--font-family` is `'Inter Variable', Inter, system-ui, …`, so both Resolve's self-hosted `Inter` and `@fontsource-variable/inter` match. The site loads `@fontsource-variable/inter`, and the guide documents it.

**D13 · Versioning and distribution.**
- Semantic versioning from `0.1.0`. While below 1.0, a minor bump may break the API and each breaking change is listed under «Breaking» in `packages/forma-ui/CHANGELOG.md`. Consumers pin an exact version.
- `npm pack` produces the artifact.
- Until publication is authorized, Resolve consumes a tarball **vendored in Resolve** (`vendor/forma-ui-0.1.0.tgz`, `"@yelison/forma-ui": "file:vendor/forma-ui-0.1.0.tgz"`) **(owner, Q2)**.
- Rejected:
  - a git dependency (workspaces plus a build step make `npm install` from git slow and fragile);
  - GitHub Packages (requires a token in Resolve's CI and in every clone).

**D14 · CI.**
- One workflow, `.github/workflows/ci.yml`, defined in Task 0.2. Each job's name becomes a required check and the shipping configuration lists the same names.
- Pages deployment is a separate workflow that runs only on `main`.

**D15 · Proposed visual changes stay proposals.**
- Button sizes 32/40/48 are not part of v0.1. Button keeps Resolve's `--button-height` (42px, 44px below 768px). The reference page shows the sizes as «Proposed» **(owner, Q3)**.
- The homepage explorer shows Button, Input and Badge in v0.1 and adds Tabs when Tabs is extracted in phase 6 **(owner, Q4)**.

## 4. Phases and tasks

**Legend**
- **Size:** S (≤ ½ day), M (≈ 1 day), L (2+ days, split before dispatch).
- **Lanes:** A (library), B (site), C (infrastructure and docs). Two code lanes run at a time, plus C.
- **Effort:** medium for routine work. High for package contracts (exports, types, CSS, peers), token generation, interactive accessibility and the Resolve migration.
- **Review:** high for the same classes, medium otherwise.

### Phase 0 · Inventory, export and scaffolding

#### Task 0.1: Plugin «Export specification» (and plugin clean-up)

- **Size / lane / effort / review:** M / C / medium / medium.
- **Depends on:** nothing.

**Files**
- Modify: `figma-plugin/code.js` and `figma-plugin/ui.html`, plus `manifest.json` for the version and an optional `menu`.
- Create:
  - `figma-plugin/src/serialize.js`, `stable-stringify.js` and `zip.js`, as pure modules concatenated or bundled into `code.js` by `figma-plugin/build.mjs`;
  - `figma-plugin/test/*.test.mjs`, run with `node --test`.
- Remove:
  - owner-specific copy from generated pages;
  - the page-05 deletion;
  - the `console.log` of node ids;
  - `figma-plugin/tokens.json` (dead data).

**Contract**
- A third button, «Export specification», sends `{type:'export'}`. The export never calls `hydrate` or `repairComponents`, so it never mutates the file.
- Output is one STORE-mode zip, downloaded once from the UI, with:
  - `meta.json`: plugin version, export date (the only timestamp), counts and per-file sha256;
  - `variables.json`: collections, modes, `codeSyntax`, values as hex or `{alias}` plus the resolved hex;
  - `styles.json` and `components.json`: sets, `propertyDefinitions`, variants and trees;
  - `pages/<page>/<frame>.json`, one per top-level frame;
  - `png/<page>/<frame>.png` at a fixed scale, with clamping detected from the PNG header.
- Each node records:
  - name and type;
  - geometry, rounded to 2 decimals;
  - auto-layout, child sizing and constraints;
  - fills and strokes with bound variables;
  - `explicitVariableModes` that differ from the parent's, so dark screens do not serialize as light;
  - text segments with style and `figma.mixed` handled;
  - instance set, variant and properties;
  - reactions by destination frame name.
- Nodes are keyed by name path with a sibling index; ids are kept as secondary data.
- Output is deterministic: sorted collections and styles, document-order children, sorted-key JSON with a trailing newline.

**Acceptance**
- `node --test figma-plugin/test` is green. It covers:
  - stable output for the same fake tree;
  - output independent of variable list order;
  - `figma.mixed` serialization;
  - alias resolution;
  - zip validity checked with `python3 -m zipfile -t`.
- In Figma, the owner exports pages 00–04 and 07. The coordinator checks the counts in `meta.json`:
  - 40 screens + 1 contract frame + 5 icons on page 07;
  - 18 component sets with 102 variants, plus the icon grid;
  - 23 `color/*` variables;
  - 8 text styles.

**Owner action:** run the export (see §7) and drop the zip's contents into `design/spec/` through the coordinator's PR.

#### Task 0.2: Workspace, tooling and CI

- **Size / lane / effort / review:** M / A / high / high.
- **Depends on:** nothing.

**Files:** root `package.json` (workspaces), `.nvmrc` (`22`), `.npmrc`, `tsconfig.base.json`, `.oxlintrc.json`, `.prettierrc.json`, `.prettierignore`, `packages/forma-ui/{package.json,tsconfig.json,vite.config.ts,src/index.ts}`, `site/{package.json,tsconfig.json,vite.config.ts,index.html,src/main.tsx}`, `.github/workflows/ci.yml`, `.github/dependabot.yml` (actions only), `scripts/herdr/project.env` (required checks).

**Contract**
- `npm ci && npm run build` builds the library, then the site against the built library.
- Library and site scripts:
  - `npm run lint` (oxlint);
  - `npm run format:check`;
  - `npm run typecheck`;
  - `npm test` (Vitest, capped workers);
  - `npm run test:browser` (Vitest browser mode);
  - `npm run e2e -w site` (Playwright);
  - `npm run pack:check` (Task 5.1 fills it in).
- Versions match Resolve's lockfile majors: React 19, TypeScript 6, Vite 8, Vitest 5, Playwright 1.63. This task also installs the browser-mode provider (`@vitest/browser` with Playwright), `axe-core` and `@axe-core/playwright`, so later tasks add no dependencies.
- `ci.yml` jobs, named here and nowhere else:
  - `Library`: lint, format, types, unit tests, browser tests, build;
  - `Site`: types, unit tests, build, i18n key parity;
  - `Site e2e`: Playwright against `vite preview`.
- Actions are pinned by SHA, with `permissions: contents: read`.

## 5. Risks

| Risk | Impact | Mitigation |
| --- | --- | --- |
| Figma export quota and accuracy: plugin output may miss dark modes (explicit variable modes) or clamp tall PNGs | implementers build from wrong specs | serializer tests with both collection layouts, PNG header check, counts verified in `meta.json`; Figma spot checks reserved for disputed frames |
| Token parity drift between Forma UI and Resolve | visual regressions in Resolve | semantic parity test against the `c3f02f8` fixture (1.1), contrast contract (1.2), Resolve's own contrast and Keycloak tests in 5.2a |
| Keycloak byte copy | Resolve CI fails on any token change | 5.2a regenerates both files from the package in one commit; documented in ADR 0002 |
| `global.css` split leaks a reset or loses one | layout shifts in Resolve | `base.css` has no element selectors (2.1); Resolve keeps its reset; e2e in Resolve runs in 5.2 |
| CSS class prefix and Resolve's `non-scoped` test strategy | Resolve tests querying class names break | Resolve tests use roles and names; a grep for class selectors in Resolve's tests is part of 5.2b's brief |
| jsdom cannot prove dialog focus containment | an inaccessible dialog ships | browser-mode tests (3.1, 3.3) |
| Hydration and flash with a language not in the URL | wrong language or a flash on first paint | no prerendered body (D6); the first-paint script sets `lang`; Review Focus 1 e2e |
| Spanish strings lost in Resolve | regressions for Resolve users | provider in `AppShell`; Review Focus 2 test |
| Vendored tarball grows Resolve's repository | repository size | one tarball (tens of KB) per version, older ones removed in the same PR |
| Pages base path `/forma-ui/` and deep links | 404 on shared links | per-route `index.html` (4.1), e2e on `vite preview` with the base |
| Two-lane contention on lockfile and i18n catalogs | merge conflicts, rework | single owner per shared file, ordering in §4 |
| Proposed Button sizes presented as real | consumers rely on a missing API | «Proposed» labels and disabled controls (D15, 4.4, 4.7) |
